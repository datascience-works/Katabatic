# TabSyn

## Model Overview

A lightweight, simplified version of the TabSyn technique for creating synthetic tabular data is called TabSyn. By training a diffusion model on a latent representation of each row, it creates mixed-type tabular data (numerical and categorical columns). New rows are then sampled from that latent space and decoded back into the original data format.

### Key Idea

TabSyn divides the creation of tabular data into two phases as first, a diffusion model learns to produce new latent vectors, which are subsequently decoded back into actual column values. Each row is initially encoded into a fixed-size latent vector (one "token" per column). This avoids using raw mixed-type data to directly train a diffusion model, which is challenging because the distributions of numerical and categorical columns vary significantly.

### Research Paper
**Mixed-Type Tabular Data Synthesis with Score-based Diffusion in Latent Space**

Hengrui Zhang, Jiani Zhang, Balasubramaniam Srinivasan, Zhengyuan Shen, 
Xiao Qin, Christos Faloutsos, Huzefa Rangwala, George Karypis
ICLR 2024 (Oral Presentation)

Code: https://github.com/amazon-science/tabsyn
Paper: https://arxiv.org/abs/2310.09656

**What was kept the same, what was changed:**

The architecture of the paper is not followed in this implementation. This method uses a frozen, randomly initialised encoder and a simple MLP decoder as a replacement of the trained Transformer-based VAE with adaptive β-VAE scheduling used in the study. With a more simple MLP base, the diffusion technique (score-based diffusion in latent space) follows to the same fundamental principle.

**Parts not specified in the paper:**

There are no such hyperparameters to refer to because the paper does not discuss a lightweight, non-Transformer version. Here, the defaults (d_token=16, diffusion_steps=50, etc.) were individually set and practically adjusted.

## Approach

TabSyn's pipeline has three stages:

1. **Encode**: each row becomes a fixed-size latent vector, one token per 
   numeric column (linear projection) and one per categorical column 
   (embedding lookup).
2. **Diffusion**: a diffusion model learns the distribution of these latent 
   vectors by adding noise and learning to reverse it.
3. **Decode**: new data is generated by denoising random noise, then 
   decoding it back into real values (inverse scaling for numeric, 
   argmax + label decoding for categorical).

### Training Details

Two separate steps: the decoder trains first to reconstruct real rows from their latent encodings (MSE for numeric cross-entropy for categorical), then the diffusion model trains on those same latents using an EDM-style denoising loss. The encoder itself is never trained, it's frozen and randomly initialized from the start.

### Convergence Criteria

Both stages use early stopping: training halts if loss doesn't improve for `patience` epochs (default 20). This isn't just for efficiency, relaxing patience to 50 caused severe mode collapse in testing, so early stopping also protects against overfitting-driven collapse.

## Hyperparameters
Found in `katabatic/models/tabsyn/models.py` (`TabSyn.__init__`).

| Parameter | Default | Notes |
|---|---|---|
| `d_token` | 16 | Latent token size. Tuned, best value found (16), confirmed via testing 8/12/16/24/32. |
| `decoder_epochs` | 50 | Not tuned. |
| `decoder_batch_size` | 2048 | Not tuned. |
| `diffusion_epochs` | 500 | Ceiling only, early stopping usually triggers well before this. |
| `diffusion_batch_size` | 4096 | Not tuned. |
| `diffusion_hidden_dim` | 512 | Paper uses 1024. Tested, 512 outperformed 1024 on this implementation. |
| `diffusion_steps` | 50 | Tested against paper's recommended value under 20. `diffusion_steps=15` matched default performance exactly. |
| `lr` | 1e-3 | Tuned, best value found was `5e-3` (tested 5e-4 to 1e-2). |
| `weight_decay` | 0.0 | Tuned, best value found was `0.01` (tested 0.0, 0.01, 0.05). |
| `patience` | 20 | Tested, increasing to 50 caused severe mode collapse. Default retained. |

**Recommended tuned configuration** (best verified result, Car dataset):
```python
TabSyn(d_token=16, weight_decay=0.01, lr=5e-3, diffusion_steps=15)
```
Composite score: 0.7098, compared to 0.6644 with all defaults.

## Input
- `X`: Tabular feature matrix (numeric and/or categorical columns)
- `y`: Target labels

### Expected Files
TabSyn expects NumPy files in `data_dir`, not CSVs directly:
- `X_num_train.npy`, `X_cat_train.npy`, `y_train.npy`
- `X_num_test.npy`, `X_cat_test.npy`, `y_test.npy`
- `info.json` describing task type and column indices

If a dataset's split directory only has CSVs (`x_train.csv`, `y_train.csv`, etc.), use `benchmarks/examples/tabsyn/prepare_npy.py` to generate the required `.npy` files and `info.json` before training.

## Preprocessing
### Numerical Features
Numeric columns are standardized (mean 0, standard deviation 1) before training. The original mean and standard deviation are stored and used to convert generated values back to real-world scale during sampling.

### Categorical Features
Categorical columns are encoded to integer indices using sklearn's `LabelEncoder`, one encoder per column. The fitted encoders are stored and used to decode generated indices back into their original category strings during sampling.

## Label Handling
The target column is treated as a categorical column internally and is placed first among the categorical columns (before the actual feature columns) when building the model's internal data layout. This ordering matters when writing code that renames or reorders TabSyn's synthetic output, since the target must be positioned to match this internal layout, not assumed to be last like in the original real data.

## Output
Generated files (when using `train()`):
- `x_synth.csv`
- `y_synth.csv`

When calling `sample()` directly, output columns are generically named (`num_0`, `num_1`, ..., `cat_0`, `cat_1`, ...) and must be renamed to match the real dataset's column order before use. See `benchmarks/examples/tabsyn/run_tabsyn_car.py` for a working example of this rename logic.

## Evaluation
`evaluate()` returns a reconstruction loss (a blend of MSE fornumeric 
columns and cross entropy for categorical columns), not accuracy or F1. Lower is better.

The full evaluation used for validation is `SyntheticEvaluationPipeline` 
(`katabatic/pipeline/evaluation_pipeline.py`), which reports 6 dimensions: 
fidelity, utility, diversity, privacy, consistency, and stability, combined into a single composite score.

## Strengths
- Handles mixed numeric and categorical columns in one unified pipeline
- Fast to train and sample compared to full diffusion-in-data-space methods
- Once bugs were fixed, produces strong fidelity scores (JSD, Wasserstein) 
  on tested datasets

## Limitations
- Simplified architecture compared to the original paper (frozen encoder, 
  no Transformer, no adaptive beta-VAE), so results are not directly 
  comparable to the paper's published numbers
- Prone to severe minority class collapse on imbalanced datasets (confirmed 
  on Adult and Shuttle), an unresolved issue
- Only validated on Car and Adult so far.

## Usage
Benchmark scripts for each dataset:
- Car: [benchmarks/examples/tabsyn/run_tabsyn_car.py](benchmarks/examples/tabsyn)
- Adult: [benchmarks/examples/tabsyn/run_tabsyn_adult.py](benchmarks/examples/tabsyn)

```python
from katabatic.models.tabsyn.models import TabSyn

model = TabSyn(d_token=16, weight_decay=0.01, lr=5e-3, diffusion_steps=15)

model.train(
    data_dir="path_to_data",
    synthetic_dir="path_to_save"
)

X_synth, y_synth = model.sample(1000)
```
