# TVAE Model

## Model Overview
TVAE (Tabular Variational Autoencoder) generates synthetic tabular data by
learning a compressed latent representation of real rows through an
encoder/decoder pair, then sampling new latent vectors and decoding them
back into realistic tabular rows.

---

### Key Idea
TVAE applies the Variational Autoencoder (VAE) framework — an encoder that
maps input data to a distribution over a latent space (mean and
log-variance), and a decoder that reconstructs data from samples drawn from
that latent distribution — specifically to tabular data. Training combines
a reconstruction loss (how well decoded rows match the originals) with a
KL-divergence term that keeps the latent distribution close to a standard
Normal prior, so new rows can later be generated by sampling fresh latent
vectors from that same prior.

---

### Research Paper
- **Paper used as base:** Xu, L., Skoularidou, M., Cuesta-Infante, A., &
  Veeramachaneni, K. (2019). *"Modeling Tabular data using Conditional
  GAN."* NeurIPS 2019. (TVAE is introduced in this paper alongside CTGAN,
  as a VAE-based baseline for the same tabular data generation problem.)
- **Underlying theory:** Kingma, D. P., & Welling, M. (2013). *"Auto-Encoding
  Variational Bayes."* — the foundational VAE framework TVAE applies to
  tabular data. The KL-divergence term used in TVAE's loss function is the
  closed-form Gaussian-case solution derived in this paper (Appendix B).
- **Official implementation used as base:**
  [github.com/sdv-dev/CTGAN](https://github.com/sdv-dev/CTGAN) — the
  paper authors' own maintained, published, pip-installable package
  (`pip install ctgan`).
- **What we kept the same:** the entire model — this port **wraps the
  official `TVAE` class directly** rather than reimplementing it, so the
  encoder/decoder architecture, reparameterization trick, loss function,
  and the `DataTransformer` preprocessing (Bayesian-GMM normalisation for
  continuous columns, one-hot encoding for discrete columns) are exactly
  as published by the original authors.
- **What we changed:** only the integration layer — a thin adapter
  (`TVAEModel` in `models.py`) that maps Katabatic's
  `train()`/`sample()`/`evaluate()` interface and file conventions
  (`x_train.csv`/`y_train.csv` → `x_synth.csv`/`y_synth.csv`) onto calls to
  the official `ctgan.synthesizers.tvae.TVAE` class.
- **Why wrap instead of reimplement:** the official `DataTransformer` uses
  a Bayesian Gaussian Mixture Model (`ClusterBasedNormalizer` from the
  `rdt` library) for continuous-column normalisation — a non-trivial,
  actively-maintained component. Reimplementing it by hand would risk
  bugs and drift from the paper's actual behaviour; wrapping the official,
  maintained package instead guarantees fidelity to the published method.

---

## Approach
1. **Encode** — the official `DataTransformer` normalises continuous
   columns via a Bayesian GMM and one-hot encodes discrete columns.
2. **Train the VAE** — an `Encoder` network maps each row to a latent
   distribution (`mu`, `logvar`); a sample is drawn via the
   reparameterization trick (`eps * std + mu`); a `Decoder` reconstructs
   the row from that latent sample. The loss combines per-column
   reconstruction loss (Gaussian for continuous columns, cross-entropy for
   discrete columns) with the closed-form KL-divergence term.
3. **Sample** — new latent vectors are drawn from a standard Normal prior
   and passed through the trained decoder, then inverse-transformed back
   into realistic tabular rows.

### Training Details
Trained with Adam optimiser (with L2 weight decay via `l2scale`), for a
fixed number of epochs, using the combined reconstruction + KL loss.

### Convergence Criteria
TVAE (via the official implementation) trains for a fixed number of
epochs with no built-in early stopping; unlike TabKDE, our epoch sweep
found TVAE's performance genuinely benefits from the full epoch budget
rather than converging early (see Performance Benchmarks below).

---

## Hyperparameters
Defined in `TVAEConfig` (`utils.py`), matching the official `ctgan` TVAE's
constructor parameters:

| Hyperparameter | Default | Notes |
|---|---|---|
| `embedding_dim` | 128 | Latent space size |
| `compress_dims` | (128, 128) | Encoder hidden layer sizes |
| `decompress_dims` | (128, 128) | Decoder hidden layer sizes |
| `l2scale` | 1e-5 | Adam weight decay |
| `batch_size` | 500 | |
| `epochs` | 300 | |
| `loss_factor` | 2 | Reconstruction loss weighting |

**Recommended configuration after tuning (car dataset):** the defaults
above were already the best-performing configuration found — no tested
variation (smaller/larger embedding dimension, smaller batch size, fewer
epochs) improved on it (see Performance Benchmarks below).

## Input
Standard Katabatic convention:
- `X`: Tabular feature matrix
- `y`: Target label column

### Expected Files
- `x_train.csv` and `y_train.csv`, **or**
- a single `train_full.csv` with the label as the last column

---

## Preprocessing

### Numerical Features
Handled by the official `DataTransformer`: normalised via a Bayesian
Gaussian Mixture Model (`ClusterBasedNormalizer`), which models each
continuous column as a mixture of Gaussian components and represents each
value as a `(mode, normalised scalar)` pair rather than a single number.

### Categorical Features
One-hot encoded via the official `DataTransformer`'s `OneHotEncoder`.

---

## Label Handling
The label column is treated as a discrete (categorical) column and passed
to the official `fit(..., discrete_columns=[...])` parameter, unless
explicitly listed under `continuous_cols` by the caller — same convention
as the TabKDE port.

---

## Output
Generated files (written by `TVAEModel.train()`):
- `x_synth.csv`
- `y_synth.csv`

(Note: like the TabKDE port, this implementation does not currently write
a `metadata.json`.)

---

## Evaluation
`TVAEModel.evaluate()` returns the same lightweight sanity-check metric as
the TabKDE port (mean absolute difference between real and synthetic
per-column mean/std for numeric columns). The project's primary evaluation
is the shared `SyntheticEvaluationPipeline` (fidelity, utility, diversity,
privacy, consistency, stability), as reported below.

---

## Strengths
- Wraps the official, published, actively-maintained implementation —
  high fidelity to the peer-reviewed method with minimal risk of
  implementation drift
- Strong performance out of the box: fidelity 0.97, utility 0.93,
  diversity 1.00, and — unlike TabKDE — a strong consistency score (0.87,
  vs TabKDE's 0.45)
- Best composite score among the two models validated so far (0.8717 vs
  TabKDE's 0.7520)

## Limitations
- **Same structural privacy issue as TabKDE**: exact-duplicate rate of
  ~83–85% across every configuration tested (baseline, embedding size,
  batch size, epoch count), driving a weak privacy score (~0.44–0.45).
  This persisted across both models built this trimester, suggesting the
  issue may be linked to the small, low-cardinality nature of the car
  dataset (only 4×4×4×3×3×3 possible feature combinations) rather than
  being specific to either model's architecture.
- A dedicated privacy-optimisation sweep (reducing network capacity via
  `compress_dims`/`decompress_dims`, increasing `l2scale` regularisation,
  reducing epochs) found that **reducing model capacity improves privacy
  (0.44 → 0.52) but at a significant cost to overall quality** (composite
  score dropped from 0.87 to 0.73, consistency collapsed from 0.94 to
  0.33). No configuration tested achieved both good privacy and good
  overall quality simultaneously — this is a genuine tradeoff, not yet
  resolved.
- Fewer training epochs noticeably hurt performance (composite dropped to
  0.80 at 100 epochs vs 0.87 at 300) — unlike TabKDE, TVAE does not
  converge early and benefits from its full epoch budget.

## Usage

```python
from katabatic.models.tvae.models import TVAEModel

model = TVAEModel(
    embedding_dim=128,
    epochs=300,
    batch_size=500,
)

model.train(
    data_dir="path_to_split_data",
    categorical_cols=["buying", "maint", "doors", "persons", "lug_boot", "safety"],
    continuous_cols=[],
)

df = model.sample(1000)
```

## Model Performance Benchmarks Results

Baseline configuration took approximately 10 seconds to train on CPU on
the car dataset (1382 training rows, 300 epochs).

### 1. Hyperparameter / epoch tuning (5 configurations)

| Config | embedding_dim | epochs | batch_size | Composite |
|---|---|---|---|---|
| **baseline (best)** | 128 | 300 | 500 | **0.8717** |
| smaller_batch | 128 | 300 | 128 | 0.8716 |
| smaller_embed | 64 | 300 | 500 | 0.8610 |
| larger_embed | 256 | 300 | 500 | 0.8536 |
| fewer_epochs | 128 | 100 | 500 | 0.7971 |

**Takeaway:** the official package's default hyperparameters were already
the best-performing configuration for this dataset — no variation tested
improved on the baseline. This is a valid "ruled out a more expensive
configuration" result per the team's benchmarking guide, rather than a
failure to find improvement. Notably, reducing epochs to 100 cost a
meaningful ~0.075 drop in composite score, showing TVAE (unlike TabKDE)
benefits from its full training budget.

### 2. Privacy optimisation sweep (5 configurations)

| Config | l2scale | compress/decompress_dims | epochs | Composite | Privacy |
|---|---|---|---|---|---|
| baseline | 1e-5 | (128,128) | 300 | 0.8717 | 0.4423 |
| strong_l2 | 1e-3 | (128,128) | 300 | 0.8716 | 0.4481 |
| **smaller_network** | 1e-5 | (32,32) | 300 | 0.7267 | **0.5249 (best privacy)** |
| fewer_epochs | 1e-5 | (128,128) | 100 | 0.7971 | 0.4447 |
| combined | 1e-3 | (32,32) | 100 | 0.7054 | 0.4071 (worst) |

**Takeaway:** reducing the model's network capacity (`smaller_network`)
gave the largest privacy improvement, reducing the exact-duplicate rate
from ~84% to ~71%, but at a steep cost — composite score fell by ~17% and
consistency collapsed (0.94 → 0.33, with the discriminator flagging
synthetic data as easily detectable). Regularisation alone (`strong_l2`)
had negligible effect on privacy. This confirms a genuine
privacy–quality tradeoff for this dataset, requiring further investigation
(e.g. targeted noise injection) rather than a solved problem.
